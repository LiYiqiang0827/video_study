# 云聪交易理论复刻工程深化框架

版本：v0.1。日期：2026年10月7日。用途：交给本地GPT检查实际环境，深化为可由Codex实施和验收的工程文档。

目标是把云聪直播中的看图、画线、判断和操作逻辑，逐步转成可追溯、可重放、可检验的规则。工程首先需要稳定的数据与图表能力，再把这些能力与直播文字、原始画面对应起来。

推荐架构是：**原始数据保留，数值数据统一整理并增量维护，图表和画线按需生成，重复结果缓存。** 日K可以跨年度查看五年、十年或上市以来的趋势；15分钟K可以查看几天或更长窗口。K线周期、观察跨度、显示缩放和画线分析窗口分别控制。

本框架确定方向和关键约束。本地GPT需要补齐真实路径、数据库结构、代码版本、参数、命令、测试样本和验收标准，形成下一份执行文档。

## 一 目标与首期边界

复刻应分为三个递进目标：

1. **复现观察对象。** 确认云聪当时看的是哪只股票、哪个周期、哪段历史、什么复权和坐标设置，能生成可比的K线图。
2. **复现判断过程。** 还原他选择的平台、趋势线、关键高低点，以及突破、回抽、失效和放弃的条件，保留题材、量能、持仓等影响判断的上下文。
3. **检验规则表现。** 用未参与规则提炼的片段检验是否能解释他的判断；规则稳定后，再开展历史回测和交易效果评估。

首期交付应是一条完整的小闭环：从现有数据库读取跨年度行情，生成日K与15分钟图，输出可解释的结构线，关联一批直播关键片段，并形成可重放的规则事件记录。

首期范围以现有20场已完成文字转录的直播为基础，先挑少量片段试验。剩余直播转录、全市场所有历史图、自动下单、模型训练和完整收益回测，放在后续阶段按需要安排。

规则提炼以云聪原始表达和画面为依据。已有交易策略或其他理论只能作为对照，不能预先替代他的规则。

## 三 数据 图表 画线与证据的分工

程序应形成四层能力，并通过稳定接口连接。

| 层 | 职责 | 主要输出 |
| --- | --- | --- |
| 行情层 | 统一股票、日期、周期、来源、复权和历史时点，返回可信的数值序列 | K线数据包、数据来源与质量说明 |
| 图表层 | 按观察跨度、视口、坐标设置和指标配置渲染 | 交互图或静态图、图表配置、坐标映射 |
| 结构层 | 生成平台、趋势线、通道和关键点候选，解释为何保留或淘汰 | 结构对象、锚点、参数、评分与失效条件 |
| 证据与规则层 | 对应直播原文、原始画面、教师标注和算法结果，形成规则事件 | 可追溯的事件记录、对照结果、规则版本 |

行情层不依赖某一种图表库；结构层输出时间与价格坐标，不只输出图片像素。教师实际画出的线与算法生成的线分别保存，便于比较。

先复用现有仓库中合适的模块，并补齐适配接口。仓库的不同分支不能仅因存在绘图代码就整体合并，需检查本地修改与依赖影响。

## 四 跨年度整合与存储策略

### 日K优先使用现有原生日线

年度文件只是存储组织方式，查询接口应把跨年度的数据当成连续序列。用户请求某只股票过去十年的日K时，程序应筛选对应股票与日期，去重、排序、检查交易日与缺口，再返回结果。

已有合格原生日线时，优先使用原生日线。1分钟聚合日线用于缺失数据的补充、独立核验或明确指定的派生序列，输出中注明来源。

1分钟数据的现有处理口径涉及09:30记录过滤等细节。用它聚合出的开盘价、成交量和成交额，必须与原生日线对比后才能替代原生日线。

### 15分钟先复用现有历史库

历史CSV来源15分钟已经有持久化存储，首期应先读通它。TDX来源15分钟通过另一适配器接入，返回的数据来源必须明确。

已查看的仓库版本中，`get_fifteenMin`主要读取TDX来源数据库。调用函数成功并不代表读取的是覆盖早期历史的CSV来源数据库。本地执行文档应明确路由，避免历史片段因默认数据源而缺失。

需要从1分钟重新聚合15分钟时，按交易日和交易时段划分，检查源数据采用区间开始还是结束时间标记，确定集合竞价、午间休市、收盘和盘中未完成K线的处理方法。不能仅以自然时间每15分钟切一刀。

### 推荐混合方案

| 内容 | 处理时机 | 原因 |
| --- | --- | --- |
| 原始CSV、压缩包、原始视频 | 保留原样 | 便于追溯和重新处理 |
| 现有日线、分钟数值存储 | 复用，按新数据增量更新 | 已有数据工程成果应继续使用 |
| 统一索引与元数据 | 一次整理，增量维护 | 保证跨年度查询与来源识别 |
| 尚未存储的派生周期 | 首次需要时计算，按使用量决定持久化 | 避免预计算大量无用结果 |
| 日K十年图、15分钟几天图 | 按请求生成 | 观察窗口与展示方式会频繁变化 |
| 画线候选与证据对照 | 按需计算并版本化缓存 | 方法和参数需要反复比较 |
| 已完成的转录与可复用帧 | 优先复用 | 避免重复消耗媒体处理时间 |

缓存键至少包含股票、周期、时间范围、历史截止时点、数据来源及版本、复权口径、画线方法与参数版本。图片缓存还要包含视口、线性或对数坐标、尺寸和显示配置。

历史复刻结果需要保留版本。新增行情可以生成新的分析结果，但不能覆盖原来“截至当时”的证据包。

## 五 行情查询契约

统一接口应能回答“哪只股票、什么周期、哪段历史、截至何时、按什么价格口径、从哪里读”。函数名与实现位置由本地GPT结合仓库决定。

| 输入或输出 | 要求 |
| --- | --- |
| 股票标识 | 使用稳定代码；名称只作展示，保留历史名称映射 |
| K线周期 | 首期支持日K与15分钟；1分钟可用于核验和特殊片段 |
| 请求起止时间 | 可以跨年度；与分析截止时点分别定义 |
| 历史截止时点 | 支持交易日内的具体时间，并明确时区和数据可用性规则 |
| 数据源 | 显式选择原生日线、CSV历史分钟、TDX分钟或派生数据 |
| 价格口径 | 原始价、指定锚点的前复权等，记录实际使用的因子与锚点 |
| 数值字段 | 开高低收、实际成交量、成交额；字段缺失用空值并说明 |
| 时间字段 | 交易日、K线区间、时间标记规则、是否完成 |
| 来源元数据 | 数据文件或数据库、版本、最新覆盖日期、异常与降级说明 |

接口发现日期范围或某个字段缺失时，应明确报告。跨来源补充要采用可追溯策略，避免静默换源或用零填充缺失值。

### 必须优先检查的五个问题

1. **跨年度复权。** 不能每年单独以前复权方式调整后拼接。保存原始价格与因子，用同一锚点生成完整查询窗口。历史复刻应指定当时可用的因子范围和调整基准。
2. **成交量口径。** 已查看的日线查询实现中，`qfq=True`除调整价格外还对`vol`做变换。首期适配器应核验该行为；若需要实际成交量，应读取原始量并把价格调整单独处理。先评估现有调用方，再决定是否修改公共函数默认行为。
3. **盘中未完成K线。** 截至10:07，10:00至10:15的完整K线尚不可见；当日日K的全天高低收和成交量也尚不可见。程序需采用已完成K线或按当时分钟数据构造的临时K线，并显式标记。
4. **时间与单位。** 核验A股交易时区、成交量是手还是股、成交额单位、开收盘记录、午休边界及重复时间戳。不同数据源不能仅按同名字段直接合并。
5. **质量与缺口。** 区分停牌、尚未上市、退市、真实无成交、文件缺失和数据库缺失。检查OHLC关系、非负量额、唯一键与跨年连续性，并保留异常报告。

价格复权用于形态分析，交易触发价格与涨跌停比较还需与原始价格对应。两种价格不能在同一规则中混用而不说明。

## 六 灵活看图的实现

同一个程序应允许如下独立配置：

| 维度 | 示例 | 工程含义 |
| --- | --- | --- |
| 周期 | 日K、15分钟K | 每根K线代表什么 |
| 观察跨度 | 十年、五年、三个月、五个交易日 | 取回和展示哪段历史 |
| 视口 | 全历史压缩、局部放大、平移 | 图上当前看到哪些K线、密度如何 |
| 分析窗口 | 长期平台、近期趋势、局部突破 | 每种方法分析哪些数据 |
| 价格坐标 | 线性、对数 | 价格距离及斜线的几何定义 |
| 历史时点 | 直播当时、收盘后复盘 | 允许使用哪些已知信息 |

十年日K大约有两千多根，短期15分钟窗口可能只有几十根。首期应实测图表库能否保留这些日K并平滑缩放。周K和月K可以辅助观察长周期结构，但切换周期必须明确，不能把“压缩日K视图”自动替换为周K或月K。

平台上下边界通常比屏幕上的线条角度更稳定。斜线应定义在时间或K线序号与价格坐标上；线性与对数坐标改变斜线含义，算法和渲染必须一致。截图上看起来很陡，不能直接等同于某个固定趋势强度。

图表库重点比较：多周期与长历史缩放、线条叠加、成交量与成交额、准确坐标映射、静态导出、Windows环境依赖、批量生成成本。先用一只股票的十年日K和几天15分钟图试验，再定实现方案。

## 七 画线方法的比较与选择

李老师仓库中的静态结构模块适合作为基线。现有资料包含关键点、包络线、趋势线与通道等方法，但默认窗口、坐标、确认规则和适用周期需要检查，尤其不能直接把日线参数搬到15分钟上。

方法优先围绕云聪实际使用的结构展开：

| 结构 | 首选方法方向 | 需要解释的内容 |
| --- | --- | --- |
| 长期大平台 | 水平价格带、重要高低点聚合、反复触及与突破 | 为何这些位置构成同一平台，区间宽度多大，哪些触及有效 |
| 趋势与回抽 | 已确认关键点连线、外侧包络、稳健趋势通道 | 选择哪些锚点，是否穿过有效价格，回抽如何确认 |
| 15分钟局部结构 | 局部平台、下降线、近期关键点 | 局部窗口、突破与收盘确认、未完成K线如何处理 |

首期建议保留两至三个可解释的候选方法：现有仓库基线，加一至两个适合具体结构的替代方法。外部项目如`trendln`与`pytrendline`可以作为比较对象；安装前检查当前代码、许可证、依赖兼容性和实际复杂度。

`pytrendline`的全量候选搜索开销较高，长达十年的日K不宜直接穷举所有组合。可限制分析窗口、锚点集合与候选数量。长期平台也不必强行用斜线搜索解决。

### 结构对象与历史确认

每条线或价格带至少保存：类型、适用周期、锚点时间与价格、起止区间、坐标模式、价格容差、触及次数、有效与失效条件、确认时点、方法版本和保留理由。

价格容差可以比较固定比例与ATR尺度，参数通过样本深化。对尚未确认的终点标记为临时状态。

若关键点需要后续若干根K线才能确认，它只能在确认完成后用于正式历史判断。过去某天的分析不能使用未来确认的拐点、未来高低点，或者完整视频后半段才出现的解释。

同一历史截止时点的结果必须可重放。随着新K线出现，候选线可以更新，但应记录更新原因和版本，区分正常更新与使用未来信息重写过去。

### 方法优劣的评价次序

先比较是否识别出云聪关注的结构、锚点和触发逻辑，再比较跨缩放一致性、小幅新增数据后的稳定性、因果正确性、可读性与计算耗时。收益与胜率属于后续独立验证，不能用事后走势反向挑选“最漂亮的线”。

## 八 直播抽帧与行情对齐

利用已完成的文字结果筛选候选事件：出现股票名称、周期切换、平台、突破、回抽、买入、加仓、卖出、止损、放弃等表达的位置，建立时间索引。

随后围绕事件查看原始画面，而不是仅靠关键词推断规则：

1. 按原视频时间定位候选片段，初始可以取前后约30秒；遇到拖动图表、切换周期或画线时，扩展到完整动作过程。
2. 复用已有帧。缺失的关键区域再加密抽帧，初始可试0.5至1秒间隔，并保留画线前、画线中、画线后的画面。
3. 增加低密度巡检或图表区域变化检测，补充没有对应口述的切换与标注。全屏场景检测可能漏掉细小线条变化，也可能被摄像头、行情闪烁干扰。
4. 用OCR和画面识别确认股票、周期、价格轴、日期轴、复权提示、鼠标指向和实际标注。不能默认抽帧程序已完成这些语义工作。
5. 对照本地行情建立像素到K线序号、时间和价格的映射。横轴有周末、节假日和停牌，不能直接按自然日线性换算。
6. 缩放或平移后重新注册坐标，保留映射可靠程度；不能定位的锚点保留未知状态，进入人工核验。

不同时间至少分开记录：视频偏移、直播或复盘的实际市场时点、图上所指K线时间、算法允许使用的数据截止时点。直播说“这里突破”可能指过去某天，文件日期也不一定就是所指行情日期。

语音静音裁剪前后的时间要映射回原视频。保留请求抽帧时刻、实际帧PTS、源视频标识与校验信息，复用现有manifest，不另造一套互不关联的时间系统。

识别股票名称时优先处理试点片段中影响判断的歧义，通过代码、画面与上下文交叉验证，不必先解决整个语料中所有名称疑问。

## 九 规则事件的数据结构

一条事件应能让人回答：当时看到了什么，关注哪种结构，满足什么条件，决定做什么，依据在哪里。

| 字段组 | 内容 |
| --- | --- |
| 身份与时间 | 股票代码、历史名称、视频标识、原始偏移、市场时点、所指K线时间 |
| 图表环境 | 周期、观察跨度、视口、线性或对数、价格复权、指标与数据来源 |
| 结构证据 | 平台或趋势线、锚点、边界、量能与形态、教师原始标注、算法候选 |
| 决策上下文 | 题材、消息、市场环境、已有持仓、前一次动作及不确定项 |
| 条件与动作 | 触发条件、确认条件、失效条件、观察、买入、加仓、卖出或放弃 |
| 操作证据等级 | 计划、教师口述已操作、画面显示委托、画面显示成交或持仓等分别记录 |
| 可追溯资料 | 原文摘录、文字段落、原帧、裁剪区域、行情包、结构与规则版本 |

未提及仓位、止损或目标价时保留空值。没有后续提到某只股票，不等于已经清仓；口述卖出也不自动等于有完整成交证据。

事件应能按股票连接到前后直播，保留计划变化、新闻退出、失败突破、删去候选和放弃交易。教师后来的解释可以关联原事件，但应区分当时理由与事后复盘。

买卖点类型可以形成词典，但不要为了填满预设分类而强行归类。先保留原话、场景和可观察条件，再逐步形成稳定规则。

## 十 首轮试点

先选约12至20个关键片段，覆盖长期平台、日线趋势与回抽、15分钟局部判断三类结构，并包含成功、失败、放弃和规则变化的样本。

2026年8月4日至7日的研究版转录可用于建立若干连续事件链；十年平台与15分钟切换样本若不在这些片段中，就从现有20场中补选。转录提示的周期和具体画线锚点，都要经原画面确认。

| 样本线索 | 原视频偏移线索 | 重点检验 |
| --- | --- | --- |
| 太辰光，8月4日与5日 | 8月4日约51:22至53:03；8月5日约15:32至18:23 | 底仓、突破回抽与题材背景，及次日消息影响下的退出表述 |
| 滨化股份，8月6日与7日 | 8月6日约48:07至48:42及1:10:28至1:11:38；8月7日约09:10至09:45 | 初次买入、加仓与次日开盘不及预期的动作是否对应不同条件 |
| 中国核建，8月4日 | 约12:01至14:43；32:02至32:33；1:02:01至1:02:27 | 1分钟信号、未及时观察、退出计划与不同时间的口述如何对应 |
| 华工科技，8月4日 | 约48:09至49:10 | 候选被放弃的依据，避免只学成交案例 |
| 长期平台与15分钟结构 | 从现有文字索引补选并核对画面 | 五年至十年平台是否被保留，以及小周期参数是否独立有效 |

以上时间用于查找原始证据，相关动作是转录中的表述，需核验原视频后再进入正式标注集。

对每个样本形成：关键文字、关键帧、可见信息截止时点、重建行情图、教师标注、各方法候选、规则事件和不确定项。先人工校准少量样本，再决定哪些步骤适合自动化。

保留一部分片段用于验收，不参与选线和调参。规则在这些片段中的判断，应只使用当时已知信息，然后与教师后续表达核对。

## 十一 实施阶段与验收

| 阶段 | 工作 | 可检查的交付 |
| --- | --- | --- |
| A 环境与数据盘点 | 读取仓库说明、AGENTS.md、配置、数据库表和现有媒体清单；少量查询 | 实际路径与版本、数据源映射、复用模块和差异清单 |
| B 统一行情接口 | 读通日K、CSV历史15分钟和必要的1分钟核验；支持跨年和历史截止时点 | 十年日K、跨年15分钟、盘中截断样本及来源说明 |
| C 图表与结构 | 实现可配置视口和坐标，接入基线及少量替代方法 | 同数据同截止时点的图表、结构对象和方法对照 |
| D 直播证据闭环 | 复用转录与帧，补关键抽帧，对齐时间和价格，记录教师标注 | 试点证据包、事件记录及需要人工判断的项目 |
| E 规则验证 | 从试点提炼规则，使用保留片段检验并记录偏差 | 规则初版、失败案例、适用边界与下一轮改进方向 |

执行文档应给出必要而具体的检查：

- 跨年拼接：股票代码、日期排序、重复键和缺失交易日；抽样比较原始记录。
- 聚合正确性：样本15分钟与日K的开高低收、量额和边界，对来源差异作解释。
- 复权一致性：含分红或送转的跨年样本，检查统一锚点；确认实际成交量口径。
- 因果正确性：盘中截断不读未来分钟，关键点未确认时不提前生效，绘图不默认带入后续行情。
- 图表与结构一致性：缩放只影响显示；改变分析窗口或价格坐标时结果变化有明确定义。
- 复用与重放：同一版本同一请求可重现，重复运行复用缓存，新增数据不覆盖旧证据包。
- 方法比较：能指出对应云聪哪一条线或平台、哪里相符、哪里不符，保留淘汰理由。

性能验收记录实际读取量、首次查询时间、缓存命中时间、渲染与画线耗时、内存峰值和缓存体积。目标阈值根据本机试验填写；不要预先承诺未经测量的毫秒级查询或全市场处理时间。

## 十二 本地GPT需要产出的执行文档

本地GPT的工作重点是把上述方向落实到真实环境。执行文档至少包含以下内容：

1. **环境事实。** 仓库位置、分支与提交、工作区状态、适用AGENTS.md、Python与依赖、配置入口和各数据库真实结构。
2. **数据路由。** 日K、1分钟、CSV历史15分钟、TDX15分钟分别如何读取，覆盖范围、来源切换条件、质量检查和错误处理。
3. **接口与结构。** 函数输入输出、历史时点语义、复权与量额口径、结构对象、事件记录及缓存键。
4. **实现选择。** 复用哪些模块、增补哪些适配器、图表库和画线方法如何取舍；说明实际依赖和许可证影响。
5. **文件与任务。** 拟新增或修改的具体文件、任务依赖、各阶段最小可运行入口和产物目录。
6. **样本与命令。** 实际存在的股票、日期、视频和时间点；能复制执行的命令、预期输出、必要检查与失败恢复方式。
7. **资源与更新。** 数据增量、缓存失效、断点续跑、并行度与资源上限；保留原始数据和已有业务的迁移方案。
8. **验收标准。** 用哪些真实样本证明读数、历史截断、图表、画线和证据对齐正确；哪些判断仍需人工校准。
9. **执行顺序。** 先跑通单只股票与少量片段，再扩大到试点；阶段完成后依据验收结果继续，常规步骤不重复要求确认。

每个待定项最终要落成“已经选择”“依赖条件与自动处理策略”或“确需用户决策”的明确结论。路径、函数或命令无法确认时标为待核验，不写成已经可执行。

本地GPT深化时可做只读盘点和小样本验证。全量数据重建、批量转录或大规模参数扫描，留到有明确任务和资源方案的执行阶段。
