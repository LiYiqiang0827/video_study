# 云聪直播选股台账｜执行任务书 v0.1

Oct 3, 2026 · @吴俊捷

## 1. 目标与边界

本任务建立一份“云聪直播选股台账”：把选定时间段内他每场直播里的选股、买卖和持仓，按发生时间如实记录，冻结后供独立评估。台账要能回答两个问题：

1. 他的选股本身，是否优于同日、同题材的其他股票？
2. 他的买卖管理（结构止损、到沽压止盈、分批出场），在选股之外额外贡献了多少？

本任务不做的事：

- 不计算收益，不给交易建议，不下单。收益评估在台账冻结后另行启动（见第10节）。
- 不建新基建。下载、转写、抽帧一律复用 ANNX / おかひな時間 现有的音视频平台（media\_platform 2.1.0）。
- 原视频、逐字稿、截图和台账只存本机或私人云盘，不上传任何公开仓库。李老师的 TradingAgent 仓库是公开的。
- 内容仅用于个人研究，不对外传播。

## 2. 流程与分工

识别与转写是技术操作，阅读理解交给GPT，核对和冻结由吴老师负责；行情数据只在冻结之后的评估阶段进入。

## 3. 范围与完整性

窗口内的直播必须全部纳入，不挑场次；缺失的场次只登记、不补造。

- **时间窗口**：由吴老师在启动前写定（建议最近3个月的全部直播），写入配置后不再改动。
- **场次清单**：列出频道在窗口内的全部直播与上传，包括会员限定、已删除、设为私密、没有保存回放的场次。每场一行：视频ID、标题、直播实际开始时间（北京时间）、时长、能否下载、内容是否完整。
- **回放优先**：完整直播回放优先于剪辑版。只有剪辑版的，标注“剪辑”，因为可能删掉了部分内容。
- **事件时刻**：事件时刻 = 直播实际开始时间 + 视频内偏移。屏幕上行情软件的时钟可读时，以屏幕时钟为准；与元数据相差超过2分钟的，记录差异。
- **交易时段**：标明事件发生在A股交易时段（北京时间 9:30–11:30、13:00–15:00）之内还是之外。
- **市场**：先确认他直播讲的是否A股。港股、美股、期货、外汇的事件照样记录，在“市场”字段标明，评估时分开处理。

## 4. 技术处理：下载、转写、屏幕识别

这一步是纯技术操作，不涉及内容判断；选股和画线都在屏幕上，所以屏幕识别和转写同样重要。

1. **下载**：用插件下载最高可用画质（至少1080p，保证屏幕上的代码、价格和坐标轴可读）与音轨，同时保存元数据（含直播实际开始时间）。每个文件记录 SHA-256。
2. **转写**：沿用平台现有配置：large-v3、CUDA、float16，5分钟分块，保留分块边界记录。输出带时间戳的逐段文本。
3. **抽帧**：固定1分钟抽样不够用。改为按画面变化抽帧（画面切换即抽一帧）；屏幕共享行情软件的时段，再加每10秒一帧；疑点处定点补抽。
4. **屏幕识别**：对抽帧做OCR，重点读取股票代码、名称、价格、时钟、持仓表、画线后的价位标注。识别结果与帧文件、视频时间戳绑定保存。
5. **股票名单校验**：识别出的代码和名称，与当日全市场证券清单匹配（只用代码、名称等身份信息，不含任何价格）。不能唯一匹配的，标“待核”。
6. **不做全文精校**：逐字稿保留识别原样。只对涉及股票、买卖、仓位、价格、画线的片段精校，前后各留30秒上下文。

## 5. 转写规范

全片如实转写，闲聊和会员问答也要完整保留；只是这些内容不做分析。

- **全文保留**：包括闲聊、他读出的会员留言、会员请他点评股票、答疑。不删减，不用摘要代替原文。
- **说话人**：标为“云聪”“会员留言”（他念出来的或屏幕上显示的）或“其他”。
- **原话不改**：识别错字只在“校正建议”列给出，注明依据（屏幕、证券清单或上下文），原文保留。
- **闲聊与一般问答**：只转写，不分析，不提取事件。例外：其中出现他本人的买卖操作或持仓披露时，按第6节提取。
- **会员请他点评的股票**：原话照录；在事件表中登记为D类，只填最少字段，不做分析。

## 6. 事件提取：分类与字段

只有A类（操作）和B类（选股）进入日后的选股评估；F类（持仓快照）用来还原他的真实组合，包括亏损的票。

| 类别 | 含义 | 是否进入评估 | 提取深度 |
| --- | --- | --- | --- |
| A 操作 | 他本人买入、加仓、减仓、卖出、止损、止盈，屏幕显示或口头明确 | 是 | 全部字段 |
| B 选股 | 当场选出并给出买点或计划，如列入自选、说明在哪里买 | 是 | 全部字段 |
| C 讲解 | 以某只股票为例讲形态、画线，未表示要买 | 否，单列 | 基本字段 + 画线 |
| D 会员点评 | 会员提问，他评价某只股票 | 否，单列 | 最少字段 |
| E 回顾 | 提到过去的推荐或操作 | 不算新选股；首次披露的过去操作记“补充披露”及披露时刻 | 基本字段 |
| F 持仓快照 | 屏幕显示持仓或组合表 | 用于还原组合 | 整表抄录 |

**A、B类全部字段（events.csv）：**

- 编号：event\_id、stream\_id
- 时间：事件时刻（北京时间）、视频偏移、交易时段内或外
- 标的：市场、股票代码、名称、名称来源（屏幕 / 口述 / 两者）
- 动作：买入、加仓、减仓、卖出、止损、止盈、观察
- 屏幕数值：价格、数量或仓位比例，只填可读到的
- 买点类型：只填他本人说出的名称（如“2B”“双突破”）；没说就填“未说明”，不得替他归入13类买点
- 计划：止损位、目标位或沽压位、计划周期，只填他说出或屏幕标出的
- 画线：线的种类（趋势线、颈线、箱体上下沿、支撑压力、量能区）、所用周期、可读的锚点日期与价格、画线前后的截图帧
- 证据：帧文件、OCR原文、原话摘录（一句以内）
- 置信度：明确 / 较明确 / 模糊；模糊的写理由
- 备注

**其他规则：**

- 同一只票在同一场直播里，每个动作各记一条；只是重复提起的，不另建事件，写进原事件备注。
- **D类最少字段**：时刻、代码、名称、会员问题原话、他的回答原话。
- **F类持仓快照**：每次屏幕出现持仓表就整表抄录一次，写入 portfolio\_snapshots.csv：时刻、代码、名称、数量、成本、现价、盈亏、仓位比例（可读的才填）。

## 7. 防偏差规则

这七条决定台账能不能当证据用，优先级高于效率。

1. **隔离行情**：提取阶段不读取任何直播时刻之后的行情、新闻或涨跌结果，GPT不联网搜索。行情只在第10节的评估阶段进入。
2. **只记看到和听到的**：不推测意图，不补全他没说的止损位或买点类型。模型不得使用自己对这些股票后来走势的知识，这类知识也不能影响分类。
3. **以首次说出为准**：选股时点以他在直播里第一次说出这只票为准；事后回顾不算新选股。
4. **规则先冻结**：分类规则在试点前写定并标版本号。之后修改必须升版，并对已处理的全部场次重跑，不能只改一部分。
5. **模糊保留**：拿不准的事件留在台账，标“模糊”，不删除；任何删除都要写明原因。
6. **全量处理**：窗口内所有可得场次按时间顺序处理，不挑场次。
7. **提取与评估分开**：提取产物冻结并记录哈希之后，评估才能读取行情。

## 8. 试点、验收与停止条件

先做3场试点，经吴老师核对通过后才批量处理。

**试点**：挑3场不同类型的直播，例如盘中直播、盘后复盘、以答疑为主的各一场。

**试点验收（建议门槛，吴老师可调整）：**

- 吴老师对照视频，核对全部A、B、F类事件
- A、B、F类股票代码识别正确率 ≥ 98%
- 事件时刻误差 ≤ 1分钟
- A、B类漏记 0 条
- 分类有争议的 ≤ 10%，争议项写进规则补充说明

**批量阶段**：每批约10场；每批抽查10%的事件，并核对全部A类事件。每批结束交一份简短状态：处理场次、各类事件数、待核数、遇到的问题。

**停止条件：**

- 代码识别率达不到门槛：先改识别方法（提高画质、加强OCR、名单匹配），不扩大批量。
- 发现直播里基本不展示买卖或持仓，形成不了A、B、F类事件：立即停止，报告吴老师重新评估。
- 不新建平台；不常驻轮询；逐段转写不用高档推理模型。转写在本地完成，GPT只做内容理解和提取。

## 10. 评估阶段：台账冻结后另行启动

本任务到台账冻结为止，不计算任何收益。冻结并经吴老师确认后，另开评估任务，按以下口径进行；可复用李老师仓库里已有的一分钟延迟执行、T+1和涨跌停约束代码。

- **入场价**：盘中事件取事件时刻至少60秒之后的第一根一分钟K线开盘价；盘后事件取次日开盘价。开盘涨停或该分钟无量，记为“买不到”，留在分母中。
- **对照组**：同日、同题材的其他股票，以及相关指数。
- **三套出场对比**：他实际宣布的卖出；按他的规则机械执行（结构止损、到沽压分批、趋势线失守和双跌破出场）；固定持有期作基准。
- **四个核心指标**：胜率、平均盈利与平均亏损之比、跳空或跌停击穿止损的频率、扣除费用后的期望收益。
- **A股约束**：T+1、涨跌停、100股取整、最低佣金。
