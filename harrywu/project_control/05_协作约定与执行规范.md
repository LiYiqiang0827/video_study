## 2. 文档流转

1. Claude 写设计说明或修订单（MD），放云盘 `Project Rocket/<工作线文件夹>/`，同时存 claude.ai 项目文档 `claude/`。
2. 一般情况：Astra 读后写执行计划，Claude 审阅出修订单，Harry 批准，Codex 执行。
3. 需要细到子任务书时（10-09 起）：Claude 直接写可执行文档，Codex 主执行体按文档执行，不经 Astra。
4. Codex 交付：本地 `C:\Project Rocket\outputs\<任务名>_<YYYYMMDD>\`（REPORT.md ≤3KB、ACCEPTANCE.json、证据）；关键文件上传云盘，回读核对 SHA256；给 Harry 的完成消息不超过 10 行。
5. Claude 验收，更新本总控（02、相关 03x、04）。
6. 给李老师的共享材料：云盘 `李老师策略/<策略名>/`；代码与报告走 GitHub `TradingAgent` 的 MrWu 分支。

云盘连接器不能覆盖文件：更新时上传新文件，旧文件改名加 `_旧版` 后缀。

## 3. 写任务书的规则

**开写前先问三个问题：**
1. 这项工作的用途是什么：观察工具、筛选器、买卖假设，还是完整交易方法？验收标准跟着用途走。
2. 它阻塞当前要做的事吗？不阻塞的遗留项不放进本轮。
3. 已有的基建、代码、数据能不能直接复用？先查再写。

**任务书必须写清：** 任务身份（ID、模型、档位、契约版本）；目的与完成条件；输入清单（真实路径）；写入白名单；接口；步骤；样例与预期（预期值要从证据计算，不写死）；验证命令；资源与停止（时限、D 盘读取资格、最多返修一次）；交付格式；常见错误（禁止事项）。不能只写一句"按文档实现"。

**子智能体用法**（出自《看图工具实现方案补充 20261008》"子智能体执行方案"一节）：
- 一个主执行体，同时最多 3 个子智能体；新上下文（`fork_turns="none"`），任务书全文作首条消息。
- 每个文件同一时刻只有一个写者；需要改别人负责的文件，向主执行体提接口变更。
- D 盘由主执行体统一管理，串行读；子智能体默认没有 D 盘读取资格。
- 单包 15–45 分钟；超过时限 1.5 倍取消并记录。每包最多返修一次。
- 交付标准 JSON；`completed` 与 `accepted` 分开。
- 档位分工：sol xhigh 做关键设计和有界审查（只读）；sol high 做实现与集成；luna max 做明确任务的实现与核验。显式写明模型和档位，不为省额度静默降档。

**无人值守模式**（Harry 常用）：不询问、不确认、不安装依赖；遇到未决事项保留未知并跳过，在报告里列出；不可逆且两可的决定才停下。

## 4. 红线

1. **不交易。** 真实交易、仓位变化由 Harry 批准。
2. **先截止，再计算。** 历史判断只用当时可见的信息；接口带 `as_of`；不能用今天的概念成分、行业划分、名称或大模型知识套过去。
3. **不改源库。** 既有数据库只读；新数据写独立目录或 overlay；修正另存版本。
4. **不补造数据。** 缺失写"未知"，不填零；不替云聪补全没说的内容；推断必须标为推断并写依据。
5. **Git：** 不 push 李老师 main，不强推；本地分支默认不 push；共享走 MrWu。
6. **2023–2024 考卷封存：** 适用于 15 分钟均线实验和题材发现系统的研究、选参与评分（不读、不预热、不缓存）。看图工具按 10-08 决定开放全部年份。
7. **安全防护到此为止。** 防的是"不小心看到未来"，不是有人蓄意绕过；不再新增符号链接、junction、写锁一类防护（看图 v2 教训）。

## 5. 控制 token 与时间

- 项目没有 token 硬上限（10-06 起），但只观察、不浪费。
- 不轮询：等完成事件再验收。不让高阶模型定时唤醒。
- AI 只读不超过 5KB 的摘要；长日志写文件。
- 计算交给本地脚本；模型读紧凑结果和关键案例。
- 每轮聚焦一个问题；完成就停，不留后台循环。
- 后台长任务必须有心跳和失活检测；状态文件写 `running` 不等于进程活着。

## 7. 汇报格式

- 执行方给 Harry 的完成消息：不超过 10 行；写是否完成、验收结果、云盘链接、遇到的问题、需要 Harry 做的事。
- Claude 给 Harry 的回复：先结论；说清哪些"完成"、哪些"验收通过"；遗留项只列一次。
- 尚未验证的内容只写一次，不在每节重复免责声明。
