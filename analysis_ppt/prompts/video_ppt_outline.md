# 云聪视频观点 PPT 大纲

你负责将已整理的视频 `analysis.json` 提炼成精简 PPT 内容计划。输入包含原分析、讲者原句、实体及各段时间、同实体关键截图，以及调用方计算的原分析文件 SHA。只依据这些输入，输出一个符合下述结构的 JSON 对象，不写 Markdown 围栏或额外解释。

## 内容与顺序

- 先列大纲：大盘观点、云聪主动分析、网友提问、本片重点。每票提供中文态度关键词和一句话结论，再展开该票的关键截图与说明。
- `stocks` 覆盖原分析中所有 `kind=stock` 的实体，按原视频首次出现的顺序排列，同票只建立一个对象。多次独立讨论保留多个 `details`，不把中间隔着其他股票的讨论改成连续操作。
- 大盘只复述原文的独立判断。没有时 `overview.market` 固定写“本片未作独立判断”，不从屏幕行情补观点，不为此添加空详情页。
- 当讲者对着指数或大盘K线讲形态、支撑压力、缺口或画线时，`market_items` 登记对应 `kind=index/market` 的实体，使用同段已核验K线截图与详情。大纲不能代替图解。市场泛论没有匹配图时只入大纲；不得借个股图冒充指数图。
- 未出现网友提问时 `overview.viewer_questions` 写“本片未出现明确的网友提问”，不编造提问、股票或提问页。其他空类别用一句话说明，不凑数。
- `overview` 的四个字段均为非空中文字符串，每项不超过65字；主动与网友概括可包括对应股票名、态度和一句话，不输出长篇复述。

## 发起来源与态度

用原分析与原句判断 `origin`，不根据截图、知名度、段落长短或自己熟悉的股票作推断：

- `self`：有依据表明讲者主动展开该票。
- `viewer`：原文明确出现网友、观众的提问或请求分析。
- `both`：同票既被主动展开，又被明确提问；详情保留不同来源的讲解。
- `unknown`：原文不足以确认发起来源。保留为提及股票，不硬归入前两类。

“会员推荐后云聪自己买入并主动复盘”不自动等于网友请求分析；只有明确请求或问答才归入 `viewer`。

`attitude` 只从以下枚举选择，`label` 用简短中文表达实际态度：

| 值 | 适用内容 | 标签示例 |
| --- | --- | --- |
| `buy_plan` | 有前提的买入或加仓计划 | 条件买入、回调再买 |
| `watch` | 分析、观察或等待，未给确定买卖动作 | 观察、等待、仅讨论 |
| `no_buy` | 讲者明确排除、不参与，并保留原因 | 不买、排除 |
| `bearish` | 明确偏空判断 | 偏空 |
| `hold` | 当前持有或保留仓位的意见 | 留仓、持有 |
| `sell` | 当前卖出意见或明确退出计划 | 减仓、目标退出 |

每票选能概括本片重点的一个态度，其他分支写入详情。不优先选择不等于绝对不买；条件买入不得写成已经买入；历史卖出不得直接变成当前卖出建议。`watch` 的“仅讨论”表示没有明确执行方向，不能改写成讲者建议关注。

## 文字规则

- `outline_sentence` 一句话说清讲者态度、最重要理由或条件，不超过58字，`label` 不超过20字。每个 `detail` 用 2—4 个短点，`heading` 为不超过9字的关键词，`text` 为不超过58字的具体说明。顶层 `title` 不超过45字，详情 `title` 不超过28字，`caption` 不超过45字。
- 当前动作、未来目标、历史回顾与资金假设分开。用“已做/曾做”“计划/目标”“假设分仓”简短区分，不把资金示例说成实盘持仓。
- 保留条件止损、仓位前提及重要价格区间；图中没有明确数值的画线位置写“图示位置”，不猜价格。预期空间或目标收益不能写成已实现盈利。
- 用户已确认“做套”在此语境等于“做T”：部分仓位低买高卖，或先卖再买以降低成本。摘要用“做T”，不要推导套牢事实。原分析的原句保持原样。
- 只复述讲者观点，不添加自己的交易建议、不查询未来行情，不补股票代码，不根据模糊金融词建立确定性公司特征。
- 面向读者的文字不附“注意”“不确定性”、审计说明、字幕编号、“约”或时钟映射误差。保留操作性质与原有条件。证据和审阅信息仍由原分析保存，不在此删改。
- 时间沿用输入分析，由导出器显示视频时间与北京时间；不生成时间、不把上传时间填为录制时间，不在正文编造时间字符串。

## 截图选择

- 每个 `detail` 仅有一张截图，`frame_path` 必须原样取自 `analysis.entities` 中同一 `entity_id` 的 `segments[].frames[].path`，且匹配该段内容。路径为分析目录内已登记的 PNG/JPEG，不可借其他股票的画面，不可生成路径或网络图片。
- 详情 `title` 包含可读的股票或指数名称与该段重点，保持28字以内，单页也能看出讲解对象；`caption` 简述画面与讲解的对应。原文或已登记视觉依据没有的画线、价格和形态，不补写。
- 每票 `details` 至少一项。调用前应先补齐所有股票的匹配截图；缺图不具备可导出条件，不能省略该票、给空详情或借图来冒充完整计划。匹配路径本身不代表已经视觉核验。
- 默认省略 `crop`，完整保留原图。只有输入提供已核对的裁边比例时才原样使用 `crop`；`left/top/right/bottom` 分别表示从对应边裁掉的比例，每项大于等于0且小于1，要求 `left + right < 1`、`top + bottom < 1`，不是右下角坐标。只裁软件菜单或边栏，价格、日期、成交量及原画线须全部保留。
- 字幕名与画面名不一致时，原音频名称和引用保留；仅当 `visual_identity.visual_verified=true` 时，可用 `visual_identity.display_name` 写标题和读者文案。不自行纠错或猜股票代码。指数同样按原帧确认。
- 一条字幕可能跨过两个讲解对象。此时不能直接把整句作为同对象短片；由原帧与对齐原句核验后，在分析段登记 `ppt_clip_bounds`，保留原字幕时间不变。画面仅闪现且无法保留完整同对象分句时，详情设 `embed_video=false` 并登记内部 `video_omission_reason`，只展示截图。不为凑短片长度引入相邻股票。

## 输出契约

`analysis_sha256` 原样使用调用方提供的整个 `analysis.json` 文件 SHA，不自行计算或改成片段 SHA。`entity_id` 原样使用输入实体 ID。除可选 `crop`、`market_items` 及详情的 `embed_video/video_omission_reason` 外，下面所有字段都需要；不增加其他字段。旧版股票计划可省略 `market_items`；新计划没有市场图解时设为空数组。每个市场项结构同股票项但不含 `origin`，字段为 `entity_id/attitude/label/outline_sentence/details`，态度用同一枚举。以下是结构示例，不是本片答案：

```json
{
  "schema_version": "yuncong_ppt_plan_v1",
  "analysis_sha256": "调用方提供的原分析文件SHA256",
  "title": "视频观点摘要",
  "overview": {
    "market": "本片未作独立判断",
    "self_analysis": "按原文概括主动分析股票与主要态度。",
    "viewer_questions": "按原文概括网友提问股票与答复。",
    "focus": "用一句话概括本片重点。"
  },
  "market_items": [],
  "stocks": [
    {
      "entity_id": "输入中的实体ID",
      "origin": "self",
      "attitude": "buy_plan",
      "label": "条件买入",
      "outline_sentence": "等待原文给出的条件出现后，讲者计划再考虑参与。",
      "details": [
        {
          "title": "参与条件",
          "points": [
            {"heading": "条件", "text": "简述该段明确的参与条件。"},
            {"heading": "仓位", "text": "仅在原文有依据时说明仓位前提。"}
          ],
          "frame_path": "同一实体已登记的原始截图路径",
          "caption": "该段讲解所对应的股票与图示位置。"
        }
      ]
    }
  ]
}
```

输出前逐票核对发起来源、态度与行动性质、反复讨论的独立段落，以及截图实体。不要将示例股票、示例仓位或示例句式当成原视频事实。
